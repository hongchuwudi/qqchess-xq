  2. 密钥派生流程

  密钥来源于 登录回包 TResponseLogin 中的 sSecKey 字段：

  登录响应 → { uUin, sSecKey }
                ↓
      tempKey = uUin 转字符串 → 16 字节（不足补 0x00）
                ↓
      sSecKey 的 hex 字符串 → Uint8Array
                ↓
      realKey = TEA_decrypt(sSecKey_bytes, tempKey)   ← TEAUtils.zJb()
                ↓
      realKey 存入全局变量，作为整个会话的加解密密钥

  代码位置：JCEProtocol 模块 881，line 8644，消息 ID 85001 的回调：

  [85001] = function(pkg, body) {
      keyStr = body.sSecKey;           // 服务端下发的加密过的密钥
      uin = body.uUin;

      tempKey = new Uint8Array(16);
      for (i = 0; i < String(uin).length; i++)
          tempKey[i] = uin.charCodeAt(i) & 0xFF;  // uin 作为临时密钥
    
      realKey = new Uint8Array(16);
      TEAUtils.zJb(hexToBytes(keyStr), tempKey, realKey);  // 解密出真正的会话密钥
  }

  总结： 这是一个典型的 自定义 TEA-CBC + 服务端下发密钥
  的对称加密方案。密钥不在客户端硬编码，而是由服务端在登录时动态下发（本身也经过 TEA
  加密保护），会话密钥绑定用户 uin。消息级的 iFlag 位控制是否加密切换，保证了灵活性。
